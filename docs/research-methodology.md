# Research Methodology

This project is evidence-driven. Research notes should separate confirmed observations from inference and speculation.

## Evidence Levels

Use one of these labels when documenting technical findings:

| Label | Meaning |
|-------|---------|
| Confirmed | Directly observed from a local user-owned copy, reproducible tool output, debugger session, or documented public source |
| Inferred | Reasonable conclusion from repeated observations, but not yet directly proven |
| Hypothesis | Plausible explanation that still needs validation |
| Unknown | Area not yet investigated or not enough evidence to classify |

## Observation Format

Research notes should include:

- target version or disc identifier, when known
- local command or tool used, when applicable
- input type, without committing proprietary data
- observed behavior or structure
- evidence level
- remaining uncertainty
- next validation step

## Repository Rules

Do not commit ISO contents, extracted game files, executable binaries, copyrighted assets, long copyrighted text, audio, video, textures, models, cutscenes, or copied proprietary source.

Acceptable research artifacts include original notes, checksums, file names, offsets, sizes, structural descriptions, synthetic fixtures, scripts, and reproducible commands that operate on a local copy supplied by the user.

## Validation Priority

Prefer small repeatable observations over broad architectural claims. A useful finding should help another contributor reproduce the same conclusion using their own legally obtained copy.
